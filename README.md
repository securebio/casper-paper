# CASPER data paper

Data and code for:

Justen, L. et al. Deep untargeted wastewater metagenomic sequencing from sewersheds across the United States. medRxiv 2026.03.05.26345726 (2026) [doi:10.64898/2026.03.05.26345726](https://doi.org/10.64898/2026.03.05.26345726)

Raw sequencing data is on the NCBI SRA under BioProject PRJNA1247874.

## Setup

Python 3.11 or later.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

`cartopy`, used only by the sampling map, needs the GEOS and PROJ system
libraries. On macOS `brew install geos proj`; on Debian or Ubuntu
`apt install libgeos-dev libproj-dev`. The map also downloads Natural Earth
shapefiles the first time it runs, and caches them.

The map legend uses Avenir where available and falls back to a stock sans-serif
otherwise, so the figure renders everywhere but the type differs from the
published version off macOS.

## Running

Rebuild every figure and table:

```bash
python code/run_all.py
```

It runs from any directory, writes to `figures/` and `tables/`, and reproduces
those directories exactly. Build a subset by name, and list the names with
`--list`:

```bash
python code/run_all.py --list
python code/run_all.py fig-4 tbl-s4
python code/run_all.py --verbose          # show the statistics each stage prints
```

`code/index.qmd` produces the same outputs as a rendered notebook, with the
statistics and tables inline. It needs [Quarto](https://quarto.org) and must be
rendered from `code/`:

```bash
cd code && quarto render index.qmd
```

Pass `--no-execute-daemon` when you have just edited a script, or Quarto may
reuse a cached kernel holding the previous version.

## Layout

| | |
|---|---|
| `data/` | inputs |
| `code/` | the scripts that read `data/` and write `figures/` and `tables/` |
| `figures/` | generated figures |
| `tables/` | generated tables |

`figures/` and `tables/` hold nothing but generated output; deleting either and
re-running rebuilds it.

### Inputs

Most of `data/` is per-sample output from the [SecureBio viral metagenomics
pipeline](https://github.com/securebio/nao-mgs-workflow) — taxonomic profiles,
relative abundances, virus hits and QC statistics, keyed by BioSample
accession. This repository does not run that pipeline.

These come from elsewhere:

- `lit_review_table.tsv` — published wastewater sequencing studies, compiled by hand.
- `sequencing_cost_table.tsv` — NHGRI sequencing cost series.
- `sewershed_ids.tsv` — NWSS sewershed identifiers for CASPER sites.
- `nwss_pcr_data.csv`, `clinical_testing_data.csv` — wastewater PCR from the CDC NWSS portal and weekly respiratory testing counts from Massachusetts General Hospital.

`pmmov_qpcr.csv` and `lineage_calicinet_source.csv` record the PMMoV qPCR
measurements and the published CaliciNet surveillance series the manuscript
draws on. Nothing in `code/` reads them; they are here as the source behind
those numbers.

`data/sra_statistics/` is a snapshot of SRA holdings taken 2026-03-31.
`code/query_sra_statistics.sh` refreshes it and needs the `gcloud` CLI with
BigQuery access and a billing project in `BQ_PROJECT_ID`; it is not part of
building the figures.

The two largest files are gzipped. The loaders read either form.

### Ribodepletion status

`data/sample_metadata.csv` carries a `ribodepletion_status` column with three
values:

- `none` — University of Missouri libraries, which are not rRNA-depleted.
- `ribopool` — SecureBio libraries prepared with Pan-Bacterial RiboPOOLs probes.
- `ribopool_omitted` — SecureBio libraries from which the probes were omitted through a reagent preparation error, covering samples collected 2025-05-13 to 2025-07-01 inclusive (22 samples).

The column is specific to this repository and is not part of the SRA metadata.
It is derived from the sequencing laboratory and the collection date rather than
transcribed per sample. Regenerate it with:

```bash
python code/add_ribodepletion_status.py          # --check to report without writing
```

A separate enzymatic rRNA pretreatment was applied to some University of
Missouri samples from Columbia, MO collected 2024-01-02 to 2024-03-19. That is a
different treatment, and data from samples processed under several conditions
were merged before release, so the column records probe-based depletion only.
